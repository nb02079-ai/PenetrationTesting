# LOGION 랩 — VM 공통 규칙 (먼저 읽기)

> 기준: 팀 공유문서 v3 (2026-11-02) · VirtualBox 단일 구성 · GNS3 미사용
> 각자 자기 VM 작업지시서(01~10)를 보고 빌드 → OVA로 공유드라이브 업로드.

## 1. 내부 네트워크 이름 (철자까지 전원 통일)
| 대역 | CIDR | 내부망 이름 |
|---|---|---|
| 외부(공격자) | 10.10.99.0/24 | `LOGION-wan` |
| DMZ | 10.10.10.0/24 | `LOGION-dmz` |
| 내부서버망 | 10.10.20.0/24 | `LOGION-srv` |
| 사내업무망 | 10.10.30.0/24 | `LOGION-office` |
| 보안관제망 | 10.10.40.0/24 | `LOGION-soc` |

- VirtualBox 설정 → 네트워크 → "다음에 연결됨 = **내부 네트워크**", 이름 칸에 위 이름 입력(옵션 안 보이면 상단 **Expert**).
- 이름이 한 글자라도 다르면 같은 대역이라도 **통신 안 됨**.

## 2. 절대 규칙 3가지
1. **IP 고정** — 전부 netplan(또는 OS)로 static. 방화벽 룰·DB 권한이 IP 기준이라 바뀌면 다 깨짐.
2. **OOB(soc) NIC엔 게이트웨이 금지** — 감시대상 VM의 어댑터2(`LOGION-soc`)에는 IP만, GW는 넣지 않음. 기본 GW는 어댑터1에만.
3. **직렬 2방화벽 라우팅** — DMZ→내부(srv/office)는 pfSense#1에 정적경로로 넘김(07·08 참고).

## 3. 공통 계정/이름 규칙
| 항목 | 값 |
|---|---|
| OS 계정 | `logion` / 비번 `1234` (admin은 Ubuntu 예약어라 불가) |
| Server/host name | 역할명 (webapi / mariadb / bastion …) |
| VM 이름 | `LOGION_역할` (예: LOGION_MariaDB) |
| OVA 파일명 | `LOGION_역할_v1.ova` |

## 4. 빌드 중 인터넷 (apt·git)
- 필요하면 **어댑터3 = NAT** 임시 추가 → 작업·검증 끝나면 **제거**(격리 유지).

## 5. OVA 내보내기 공통 설정
- `sudo poweroff` → VirtualBox → 가상 시스템 내보내기 → 형식 **OVA 1.0**
- **MAC 주소 정책 = "모든 네트워크 어댑터의 MAC 주소 새로 생성"** (중복 충돌 방지)
- NAT(어댑터3) 제거 후 내보내기 → 파일명 규칙대로 → 드라이브 업로드.

## 6. 자원(16GB) — 시나리오별 필요한 VM만 ON
- Wazuh(8GB) 켤 땐 Kali·Suricata 같이 안 띄우기. 통합테스트 때만 한 PC에 모음.
