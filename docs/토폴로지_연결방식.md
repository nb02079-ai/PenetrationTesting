# LOGION 모의해킹 랩 — 토폴로지 연결 방식 (as-built)

> 2026-11-04 기준 · VirtualBox 단일 가상화(GNS3 미사용) · 호스트 16GB×다수 → **2-PC 분산**

## 1. 한눈에 보기
```
                        [ PC-1 : 데이터망 전체 ]
   Kali(공격자)                                              
   10.10.99.10                                               
      │  LOGION-wan (내부망)                                 
      ▼                                                      
  ┌─────────┐  WAN                                           
  │pfSense#1 │ 10.10.99.1                                    
  │ (Edge)  │  LAN 10.10.10.1                                
  └────┬────┘                                                
       │  LOGION-dmz (내부망)                                
   ┌───┴───────────────┐                                     
   │ WAF 10.10.10.5    │  WebAPI 10.10.10.20                 
   └───┬───────────────┘                                     
       │  LOGION-dmz                                         
  ┌─────────┐  WAN 10.10.10.254                              
  │pfSense#2 │  LAN(srv) 10.10.20.1                          
  │(Internal)│  OPT1(office) 10.10.30.1                      
  └──┬───┬──┘                                                
     │   └── LOGION-office (내부망) : 직원PC·협력업체         
     │  LOGION-srv (내부망)                                  
   ┌─┴──────────────────┐                                    
   │ MariaDB 10.10.20.10 │ Bastion 10.10.20.6                
   └─────────────────────┘                                   

   ─ ─ ─ ─ ─ ─ ─ ─ 관제망(soc)만 PC를 건넘 ─ ─ ─ ─ ─ ─ ─ ─
   WAF·WebAPI·MariaDB·Bastion 의 soc NIC (10.10.40.x)
        │  LOGION-soc  = 브리지 어댑터(같은 공유기 유선)
        ▼
   [ PC-2 ]  Wazuh 10.10.40.100  (SIEM)
```

## 2. 핵심 — 연결 방식 2가지를 섞어 씀
| 구분 | 연결 방식 | 쓰는 곳 | 이유 |
|---|---|---|---|
| **데이터 경로** (wan·dmz·srv·office) | VirtualBox **내부 네트워크(Internal Network)** | PC-1 안의 모든 VM | 한 PC 안에서 세그먼트를 L2로 격리, pfSense가 경계 통제. 외부로 안 샘 |
| **관제망** (soc) | VirtualBox **브리지 어댑터(Bridged)** | PC-1↔PC-2 를 잇는 soc NIC | 내부 네트워크는 PC를 못 넘음 → 무거운 Wazuh를 2번째 PC로 빼면서, soc만 브리지로 PC 경계를 넘김 |

> **용어 주의**: VirtualBox "내부 네트워크"는 **격리 방식**(이 VM들끼리만 통하는 가상선)이란 뜻이지, "회사 내부망"이 아님. 랩의 `LOGION-wan`은 이름이 wan이어도 VirtualBox에선 "내부 네트워크" 타입으로 만든 **격리된 가짜 외부(인터넷) 구간**임.

## 3. 세그먼트 · 내부망 이름 (철자 전원 통일)
| 대역 | CIDR | 내부망 이름 | 역할 |
|---|---|---|---|
| 외부(공격자) | 10.10.99.0/24 | `LOGION-wan` | 격리된 "인터넷" — Kali + pfSense#1 WAN |
| DMZ | 10.10.10.0/24 | `LOGION-dmz` | WAF·WebAPI, 경계/내부 방화벽 사이 |
| 내부서버망 | 10.10.20.0/24 | `LOGION-srv` | MariaDB·Bastion |
| 사내업무망 | 10.10.30.0/24 | `LOGION-office` | 직원PC·협력업체 |
| 보안관제망(OOB) | 10.10.40.0/24 | `LOGION-soc` | Wazuh·(Suricata) + 감시대상 서버의 soc NIC |

## 4. VM별 어댑터 · IP (as-built)
| VM | PC | 어댑터1 (업무망/내부) | 어댑터2 (soc) | 비고 |
|---|---|---|---|---|
| Kali | 1 | `LOGION-wan` 10.10.99.10 / GW .1 | — | 공격자 |
| pfSense#1(Edge) | 1 | WAN `LOGION-wan` 10.10.99.1 · LAN `LOGION-dmz` 10.10.10.1 | — | 경계 방화벽 |
| pfSense#2(Internal) | 1 | WAN `LOGION-dmz` 10.10.10.254 · LAN `LOGION-srv` 10.10.20.1 · OPT1 `LOGION-office` 10.10.30.1 | — | 내부 방화벽(원 ASAv 자리) |
| WAF | 1 | `LOGION-dmz` 10.10.10.5 / GW .1 | **브리지** 10.10.40.5 | nginx+ModSecurity |
| WebAPI | 1 | `LOGION-dmz` 10.10.10.20 / GW .1 | **브리지** 10.10.40.20 | 포털·API·업로드 |
| MariaDB | 1 | `LOGION-srv` 10.10.20.10 / GW .1(=20.1) | **브리지** 10.10.40.10 | DB |
| Bastion | 1 | `LOGION-srv` 10.10.20.6 / GW .1(=20.1) | **브리지** 10.10.40.6 | 점프호스트 |
| Wazuh | 2 | `LOGION-soc` **브리지** 10.10.40.100 (GW 없음) | — | SIEM (+관리용 호스트전용 192.168.56.50) |

- soc(어댑터2)는 **게이트웨이 없음** — OOB 평면. 기본 GW는 업무망 NIC에만.
- soc NIC는 전부 **같은 공유기에 유선 브리지**, IP는 10.10.40.x static(공유기 DHCP 무시).

## 5. 라우팅 (세그먼트 간)
- **DMZ 호스트(WAF·WebAPI)**: 외부행 → pfSense#1(10.10.10.1), 내부서버망(srv)행 → pfSense#2(10.10.10.254)로 직접. (WebAPI→MariaDB 가 이 경로)
- **pfSense#1**: 정적경로 `10.10.20.0/24, 10.10.30.0/24 → 10.10.10.254`(pfSense#2).
- **pfSense#2**: 기본 GW = 10.10.10.1(pfSense#1). srv/office 호스트의 GW = 각 10.10.20.1 / 10.10.30.1.
- **내부-내부 NAT 안 함**: WebAPI→MariaDB 출발지가 10.10.10.20 그대로 보여야 MariaDB grant(`logion@10.10.10.%`)가 매칭됨.
- **soc(관제)**: 라우팅 없음. 각 서버의 soc NIC가 브리지로 Wazuh(10.10.40.100)에 직접 L2 도달.

## 6. 방화벽 정책 (요지)
- **pfSense#1 WAN**: 외부(Kali) → **WAF(10.10.10.5) TCP 80/443만 허용**, 그 외 차단. → 외부에서 WebAPI(.20) 직접 접근 불가.
- **pfSense#2**: DMZ→srv 는 `WebAPI → MariaDB:3306`만, office→srv 는 `협력PC → Bastion:22`(CASE 3)만 허용.

## 7. 공격 트래픽 흐름
```
Kali(10.10.99.10) → pfSense#1 → WAF(10.10.10.5) → WebAPI(10.10.10.20)
     → pfSense#2 → MariaDB(10.10.20.10)
   (모든 감시대상 로그 → soc 브리지 → Wazuh 10.10.40.100)
```

## 8. 설계 의도 (요약)
- 16GB 한 대에 전부는 무리 → **데이터망(1PC) + Wazuh(별도 PC)** 로 분리.
- 분리하되 **데이터 세그먼트는 내부망 그대로** 두어 pfSense의 경계 통제를 100% 유지(과제 평가 핵심).
- **PC를 넘어야 하는 관제망만 브리지** 1개로 연결 → 분산과 세그먼트 보존을 동시에 달성.
